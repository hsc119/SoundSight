无STM32实验版软件使用说明

按此前SSCOM离线传输的逐步操作见同目录“串口部署.txt”。
可直接下载的固定包在release/output/soundsight-pynq-serial.zip；重建入口package_serial.py。

PC复现（本工程目录）：
python -E -s -B -X utf8 software/tests/test_software.py
python -E -s -B -X utf8 software/tests/test_application.py
python -E -s -B -X utf8 software/tests/test_smp.py
前者原S1 4705项与桥接/客户9项，后者HWH寻址/保存失败/中断保帧8项。
PC测试按环境变量、根目录tools.local.env、PATH的顺序找GCC；用GCC_ROOT或SS_GCC配置，不提供个人安装路径默认值。PC DLL不能给ARM运行。

以后由A完成DDR/MIO/PYNQ并加载配套bit/hwh后，在目标板项目目录执行：
sh software/ps/build_solver.sh
python3 software/ps/run_capture.py --hwh 实际设计.hwh --output records.jsonl --mode bist-reject
python3 software/ps/run_capture.py --hwh 实际设计.hwh --output records.jsonl --mode bist-pass
python3 software/ps/run_capture.py --hwh 实际设计.hwh --output records.jsonl --mode real --frames 100
本轮没有执行这些目标板命令；不自动加载bit、复位或开启运动。

地址从实际HWH里的bd_ps_link实例读取，默认实例名ps_link；改名可用--ip指定。
document/evidence/migration/native/ps/interface.hwh记录BD准备时的寻址，仅供对照；PC测试夹具在document/evidence/inherited/ps/bd_preparation/interface.hwh。二者都不是已构建位流的配套运行文件。
默认ARM库software/ps/libss_solver.so；--library可更改。库先加载成功才访问MMIO。
Linux文件锁防止本程序重复运行；不能阻止另一个绕过本程序的MMIO工具。
每帧JSONL先write/flush/fsync成功，再CONSUME。介质本身的掉电行为仍由实际存储决定。
保存失败或Ctrl+C时finally停用，不消费失败帧。硬件只有两个公共槽，长时间不取会按冻结规则丢新并记账。

异常后保留原位流、FCLK和缓存，用以下方式只保存剩余记录，不启动新采集：
python3 software/ps/run_capture.py --hwh 实际设计.hwh --output recovery.jsonl --drain-existing
普通总线复位与STOP不清槽；重新配置PL、冷复位/失钟冷恢复会清状态，不属于保记录恢复。

双核PYNQ入口（2026-10-20，按SoundSight的PL/PS迁移分工由C接续）：
项目来源只有 https://github.com/TophBeifong1744/SoundSight 。
两个ARM核运行同一个Linux/PYNQ：默认CPU1的Python进程用ctypes调用B的ARM Linux C共享库，
负责唯一MMIO、锁帧、角度提交和消费；CPU0的Python进程负责启动/退出、JSONL落盘和显示。
这不是两块板，也不是一核Linux、一核裸机。C算法只在CPU1执行一次，不在CPU0重复计算。
原run_capture.py保留为单进程诊断入口；正式双核入口为run_smp.py。

目标板先由A检查两个核均在线且允许当前进程使用：
python3 -c "import os; print(sorted(os.sched_getaffinity(0)))"
默认应包含0、1；程序实际记录两进程PID与CPU affinity，不能靠启动了两个进程就称双核已验证。
如果仍用旧实验的maxcpus=1或CPU1裸机配置，应由A恢复匹配PYNQ的双核Linux启动配置；
不要向已由Linux管理的CPU1下载旧裸机ELF。本程序不改启动参数、不加载位流或释放第二核。
Python标准库外仅worker依赖目标PYNQ；B交ARM Linux .so或在目标板用既有build_solver.sh编译。
同一次A导出的bit/HWH须已加载；本机Windows DLL、arm-none-eabi ELF均不适用。

在目标板项目根目录运行（这些是交给A的操作，未在本机执行）：
python3 software/ps/run_smp.py --hwh 实际设计.hwh --output reject.jsonl --mode bist-reject
检查停止原因、处理已有槽后，下一轮显式清STOP历史位：
python3 software/ps/run_smp.py --hwh 实际设计.hwh --output pass.jsonl --mode bist-pass --clear-faults 0x40
python3 software/ps/run_smp.py --hwh 实际设计.hwh --output real.jsonl --mode real --frames 100 --clear-faults 0x40
--host-cpu/--worker-cpu可指定两个不同且允许使用的核，默认0/1。
不要复制清错掩码去清未查明的溢出/看门狗/协议故障；未显式选择的历史故障会拒绝启动。
程序只自动清本次启动STOP新增的取消位；startup记录保存故障原值及显式清错选择。

进程间一次只允许一条记录待确认：CPU0 write/flush/fsync成功才ACK，CPU1收到当前ACK才继续。
ACK最长等待250ms；取帧、排空仍各用原250ms上界。软件调度不提供硬实时保证，不能据此宣称零丢帧。
父进程5秒启动等待、750ms失联检测仅用于进程管理，不改变服务预算。
退出、磁盘满、ACK错误/超时、断连、C桥错误或设备故障会请求STOP，保留未消费帧。
如果C或驱动完全挂死，父进程只能有界终止子进程并报告STOP未确认，由A检查现场和看门狗。
恢复时不重新加载bit，使用run_smp.py相同HWH和--drain-existing；不允许恢复模式重发动作。
已落盘但未收到ACK/未消费的记录可能在恢复中重复保存，以同一PL运行期间的帧号关联。
冷复位后帧号可重新开始，不能跨冷复位仅凭帧号去重；输出按运行批次选新文件。

水平闭环需A确认标定、硬件限位和看门狗预算后现场执行，默认不开启。
CLI必须同时显式提供--mode real --horizontal-motion --servo-config 标定.json --watchdog-ticks 约定周期数。
标定.json为七个整数数组，机械参数必须来自实际标定：
offset_q8、direction、domain_min_q8、domain_max_q8、mechanical_min、mechanical_max、servo_max。
不能默认采用示例90度偏置或0..180机械范围。BIST始终禁止实物动作。
参数须满足现有C合同：offset_q8在[-8388608,8388607]，direction为±1，
-46080<=domain_min_q8<=domain_max_q8<46080，0<=mechanical_min<=mechanical_max<=servo_max<=511，servo_max非零。
软件只提前检查配置合法性；映射、整数舍入和正式方向继续由B的C库完成。
保存计算结果后才能COMMIT；COMMIT后未读到故障只记commit_no_fault_observed，
动作记录也保存后才消费。该记录不证明机械到位；失败帧恢复只保存，不重放旧命令。

当前公共库/寄存器仅有二维方位及水平轴，垂直有效位必须为0。
用户选定的STM32双轴版本仍需B提供相应ARM Linux调用接口、A提供匹配双轴寄存器和硬件；
C收到后接合，不另造第二套接口，也不把当前水平自测称作双轴完成。
